# 조사와 검증 기준

## 범위와 수집

첫 대상은 SK하이닉스(000660)다. Manager가 Asia/Seoul 실행 시각을 고정하고 정확히 직전 168시간을 지정한다. 주요 사건은 최대 3개로 제한한다. 같은 자료를 역할마다 무제한 다시 수집하지 않으며 Reviewer는 핵심 원문을 독립 확인한다.

1. SK하이닉스 공식 IR·공시·뉴스룸
2. DART 공개 공시, KIND
3. 관련 기업 공식 발표
4. 연합뉴스·Reuters 공개 원문
5. 추가 자료는 필요와 허용 범위를 먼저 설명

API 키나 구독을 요구하지 않는다. 유료벽과 접근 차단을 우회하지 않는다. 모든 요청은 정상 TLS 검증과 플랫폼의 네트워크 경로를 사용한다. 응답을 받지 못했으면 원문을 읽었다고 기록하지 않는다.

## 사건과 해석

- 제목·게시일·사건일·URL·조회시각·근거 구절을 저장한다. 사건일이 불명확하면 null로 남긴다.
- 새 게시물이 과거 사건을 반복하는지 확인한다. 과거 사건은 배경으로만 쓰며 현재 변화로 제시하지 않는다.
- 사실은 원문이 직접 뒷받침하는 내용이다. 해석은 사실에서 도출한 조건부 판단이며 사실과 별도 표시한다.
- 직접 기업 변화와 산업 변화를 구분한다. 매출·수익성·현금흐름·설비투자·위험요인에 이르는 경로와 전제조건을 쓴다.
- 반대 근거와 판단 유보 사유, 앞으로 볼 지표·공시·일정을 함께 제시한다.
- 주가 반영 여부는 가격·시점·시장기대 근거 없이는 확정할 수 없다. 새로운 공개 사실과 시장의 미반영 정보는 같은 뜻이 아니다.

## 독립 검토

Reviewer는 출처·숫자·날짜·인과관계·반대 근거를 확인하고 지적 사항을 남긴다. 실제로 원문을 재확인한 출처만 `checked_source_ids`에 기록한다.

| 결과 | 의미 |
|---|---|
| PASS | 검토 대상의 근거·표현을 확인했고 미해결 중대 문제가 없음 |
| REVISE | 수정이 필요한 사실·논리·표현 문제가 있음 |
| INSUFFICIENT_EVIDENCE | 원문 접근 실패 또는 근거 부족으로 결론을 확정할 수 없음 |
| NOT_RUN / null | Reviewer 자체가 실행되지 않음 |

수정은 원칙적으로 한 차례다. 추가 검토가 필요하면 문제를 남기고 완료로 포장하지 않는다. 자료를 읽지 못한 상황을 “주요 뉴스 없음”으로 바꾸지 않는다. 충분히 조사하고 새 사건이 없다는 경우도, 원문이 없는 이번 차단 실행과 구분한다.

## 최종 확정 조건과 접근 경로

공식 자료와 조사기간 내 DART 공시 목록·선정 사건 관련 공시를 확인하고, 미해결 중대 지적이 없어야 최종 확정한다. 핵심 접근이 실패하면 일부 원문이 있어도 PARTIAL/INSUFFICIENT_EVIDENCE 조사 초안으로 보존한다. COMPLETED/PASS만 사이트의 확정 보고서에 포함한다.

공개 웹 조회 도구와 클라우드 Python의 네트워크 접근은 별개로 기록한다. 터미널 실패를 전체 인터넷 불가로 일반화하지 않으며, 홈페이지 접근 성공을 개별 원문이나 기간 공시 검증 성공으로 바꾸지 않는다. 검색 결과 요약만으로 사실 확인을 완료하지 않는다.

## 보존

JSON이 기준 데이터다. 같은 데이터로 Markdown을 생성한다. 실행 ID별 폴더는 불변이며 재실행은 새 ID를 사용한다. 원문 전체의 무단 복제 대신 제목·링크·검증에 필요한 짧은 근거만 보존한다. 가상 데이터는 테스트에서만 사용한다. 금융 리서치 학습 자료이며 실제 투자 권유가 아니다.
